# Systems with Judgment: AI Systems for Founders and Small Teams

A static landing page for John von Seggern and Tsotne Arbolishvili’s AI systems work with founders and small teams, rooted in music education and music technology.

## Local preview

Requires Node.js 20+ and Python 3.

```sh
npm run build
npm run check
npm run dev
```

Then open `http://localhost:3000`.

Edit `index.md` to change any homepage text and `secondbrain.md` to change
the second brain page, then run `npm run build` to regenerate `index.html` and
`secondbrain.html`. Keep the `copy:` comments in place; the paragraph below each
comment is the editable value. Markdown emphasis such as `*this*` is supported.

For layout or behavior changes, edit `_page.body.html` (homepage template),
`_secondbrain.body.html` (second brain template), `_page.css`, or `_page.js`.
The press page is hand-written HTML in `_press.body.html`, and the 404 page in
`_404.body.html`. Run `npm run build` after any of these changes. All pages
share one inlined stylesheet and script, assembled by `_assemble.py`. A
template can pull in a shared fragment with `{{include:_file.html}}`.
`npm run check` confirms the generated HTML is current and runs the copy checks.

## Deploys

The live site is **GitHub Pages**, serving the `main` branch as committed
(`CNAME` points `systemswithjudgment.com` at it). Pages are served as flat
files, so `press.html` answers at `/press` and `secondbrain.html` at
`/secondbrain`. `vercel.json` is kept for a possible Vercel move but is not what
serves the site today.

Every push to `main` runs `.github/workflows/build-pages.yml`, which rebuilds
every page (including `404.html`, which GitHub Pages shows for any missing
address) and `sitemap.xml` from the Markdown copy, runs the checks, and commits
the result back to `main` if it differs. So editing `index.md` or
`secondbrain.md` on GitHub and committing is enough to deploy a copy change;
running `npm run build` locally first just makes the bot commit a no-op.

## Booking

Every page that books ends with the same Cal.com calendar (`#book`): the
homepage, /secondbrain, /press, the industry pages and the landing page. The
embed code lives once, in `_booking.html`, exactly as Cal.com supplies it,
together with the "Open the calendar in a new tab" link. To change the event,
paste Cal.com's new embed code there and update `bookingUrl` in
`site-config.js`; the site checks fail if the two disagree. Every booking
button reads "Free 30-minute session" and jumps to the calendar on its own page.

## Analytics

Button clicks (`book_session_click`, with the button's placement), scroll
depth, the calendar scrolled into view (`calendar_viewed`), the calendar drawn
by Cal.com (`calendar_loaded`), a completed booking (`booking_completed`) and a
calendar that fails to load (`calendar_failed`) are pushed to
`window.dataLayer`. They also go to PostHog once `posthogKey` in
`site-config.js` holds a project key; while it is empty, no analytics script
loads. No setting stores cookies. `posthogCookieless: true` counts returning
visitors with PostHog's daily anonymous hash, but only after "Cookieless
tracking" is switched on in the PostHog project's settings (otherwise PostHog
drops the events); `false` counts every page load as a new visitor.

Links to the site from outreach (PDFs, emails) should carry UTM tags, for
example `?utm_source=plus8&utm_medium=pdf&utm_campaign=one-pager`. PostHog
records them with the page view, and the calendar passes them on to Cal.com.

## Search

`sitemap.xml` is generated by the build from every public page, and
`robots.txt` points to it. The 404 page and the old design snapshot
`index-b.html` carry a `noindex` tag so they stay out of search results.

## Site checks

`npm run check` requires a few exact strings: the H1, the button label "Free
30-minute session", several section headings and the NDA sentence. It also
fails on text under 13px, spaced capitals or a blinking animation in
`_page.css`. Rewording a required string on GitHub makes the deploy workflow
fail, so change `scripts/check-site.mjs` in the same commit.

## Social share card

`assets/og-image.png` is generated, not hand-drawn. Regenerate it after any
brand change:

```sh
python3 scripts/make-og-image.py
```

It needs Pillow, and caches the two typefaces in `.fontcache/` on first run.
The colours at the top of the script mirror the tokens in `_page.css`.

## Favicons

`favicon.svg`, `favicon.ico` and `apple-touch-icon.png` are generated from
the decision-node mark (grey process boxes, coral decision diamond):

```sh
python3 scripts/make-favicons.py
```

## Landing page for the referral one-pager

`/music-tech.html` ("AI automation for music, audio tech and education teams")
repeats the referral one-pager's promise, steps and examples, so a reader who
follows the PDF's link finds the same page they just read. Edit its copy in
`landing/music-tech.md` and its layout in `_landing.body.html`. Another
campaign page is one more Markdown file in `landing/`.

## Industry outreach pages

Six short landing pages cover record labels, publishers, distributors, venues
and promoters, artists and managers, and schools and education. Edit their copy
in `use-cases/*.md` and layout in `_usecase.body.html`, then run `npm run build`.
The homepage links to each page. Use the explicit `.html` URLs when sharing;
they work on both GitHub Pages and the local Python preview server.
All pages use the shared styles, script, booking configuration, and social metadata.
The build workflow regenerates these pages along with the original three pages.
